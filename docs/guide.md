# AmuzASCII

[← К описанию проекта](../README.md)

> Подробное техническое руководство. При клонировании репозитория сначала выполните `npm.cmd --prefix frontend ci` и `npm.cmd --prefix frontend run build`: собранный каталог `frontend/dist` исключён из Git. В Docker интерфейс собирается автоматически.

Веб-приложение: **Python 3.11+ / FastAPI / Pillow** и **Vue 3 / Vite**. Node.js: **20.19+ или 22.12+**. Интерфейс на русском и английском, двенадцать тем оформления и адаптивная рабочая область.

## Быстрый запуск (Windows)

Откройте терминал в корне проекта и создайте виртуальное окружение:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run.py
```

Откройте **http://127.0.0.1:8000**. Остановка сервера — Ctrl+C.

Собранный интерфейс включён в `frontend/dist`, поэтому Node.js для первого запуска не нужен. Для изменения и пересборки Vue:

```powershell
cd frontend
npm.cmd ci
npm.cmd run build
```

После сборки перезапустите Python-сервер. При использовании активированного виртуального окружения можно запускать сервер командой `python run.py`.

## Запуск в Docker

Нужен Docker с Compose v2+ и запущенным Linux Engine (например, Docker Desktop с Linux-контейнерами). Локально устанавливать Python или Node.js не требуется. Из корня проекта:

```powershell
docker compose up --build -d
```

Откройте **http://127.0.0.1:8000**. Статус и журнал:

```powershell
docker compose ps
docker compose logs -f web
```

Остановка и удаление контейнера:

```powershell
docker compose down
```

После изменений исходников снова выполните `docker compose up --build -d`. Dockerfile сначала собирает Vue в Node.js 22, затем копирует готовый интерфейс в Python 3.13 с FastAPI. Образ запускается непривилегированным пользователем, без режима reload; Compose подключает read-only файловую систему, временный /tmp, healthcheck и ротацию журналов. Один контейнер обслуживает API и интерфейс на порту 8000. Изображения обрабатываются в браузере. Видео и результаты временно сохраняются в `/data` на отдельном Docker-томе; наборы и настройки интерфейса остаются в браузере.

Если порт 8000 занят уже запущенным сервером, выберите другой порт. Скопируйте `.env.example` в `.env` и измените `AMUZASCII_PORT`, например на 8080:

```powershell
Copy-Item .env.example .env
```

При `AMUZASCII_PORT=8080` адрес будет **http://127.0.0.1:8080**. По умолчанию привязка только к localhost; для намеренного доступа из локальной сети можно задать `AMUZASCII_BIND=0.0.0.0`. Настройки браузера привязаны к адресу и порту: при переходе на другой порт перенесите свои наборы через JSON.

Проверка конфигурации без запуска контейнера:

```powershell
docker compose config --quiet
```

## Разработка Vue с горячим обновлением

Терминал 1, корень проекта:

```powershell
python run.py
```

Терминал 2:

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

Откройте **http://127.0.0.1:5173**. Vite перенаправляет `/api` на Python-сервер `127.0.0.1:8000`, поэтому дополнительный CORS не нужен. После изменения Vue пересоберите `npm.cmd run build`, чтобы изменения были видны также на порту 8000. Перезапустите Python-сервер после первой сборки интерфейса.

На macOS/Linux используйте `npm` вместо `npm.cmd`.

## Возможности

- Загрузка и перетаскивание PNG, JPG, WEBP, GIF и BMP (до 20 МБ, 25 мегапикселей). Для GIF берётся первый кадр.
- 40–1000 символов по ширине: ползунок и числовое поле с клавиатуры. Enter или выход из поля приводит значение к допустимому диапазону. Системные стрелки поля заменены кнопками в цветах темы: шаг 1, Shift+клик — шаг 10. Клавиши ↑/↓ и ручной ввод также работают; диапазон остаётся 40–1000. Число строк вычисляется с учётом пропорций моноширинного шрифта и ограничивается 2000. Размер холста и ячеек адаптируется к исходным пропорциям; чёрные поля не добавляются. Допустимое соотношение сторон — от 1:100 до 100:1.
- 14 наборов: классический ASCII, блоки, матрица, минимализм, типографика, бинарный, точки, Брайль, линии, геометрия, цифры, код, звёзды и плотный. Можно ввести свой набор до 256 символов. Лучше использовать моноширинные символы; эмодзи могут отображаться шире ячейки.
- 15 цветовых схем с градиентами, собственные цвета символов и фона. Три режима: градиент палитры, один цвет и исходные цвета. Выбор собственного цвета символов включает одноцветный режим.
- Яркость, контраст, насыщенность, гамма, инверсия символов, поворот и отражение.
- Просмотр оригинала, масштаб, сброс настроек. Подпись и время кадра находятся в отдельной строке под превью, без наложения на изображение.
- Экспорт PNG, JPEG, WebP, SVG, TXT и цветного HTML; собственное имя файла, качество JPEG/WebP 10–100%. TXT содержит символы без цвета. Настройки экспорта запоминаются.

В редакторе изображения декодируются и обрабатываются **локально в браузере**, без отправки в Python API. Предпросмотр работает в Web Worker. Различимые символы (ячейка от 3 физических пикселей, до 40 000 ячеек) рисуются непосредственно из контуров системного шрифта в конечном разрешении, без растягивания текстур и mip-сглаживания. При увеличении шрифт растрируется заново, как текст SVG. Для плотных сеток WebGL2 рисует всю сетку одним проходом через атлас символов. Сетка исходных пикселей и атлас кэшируются; коррекции и цвета применяются шейдером. Каждый символ хранится в отдельном слое текстуры с собственными mip-уровнями. Фильтрация учитывает видимый размер ячейки, чтобы при высокой детализации мелкие штрихи не превращались в полосы и муар. В обработке находится один кадр, следующий запрос заменяется самым свежим — очередь устаревших кадров не накапливается. Основной поток остаётся доступен для ползунков и интерфейса. При отсутствии Worker, OffscreenCanvas или WebGL2 используется прежняя Canvas-отрисовка. Размер видимого предпросмотра зависит от окна и devicePixelRatio. Для плотных сеток внутренний растр дополнительно увеличивается перед уменьшением до видимого размера, сохраняя все выбранные ячейки. На низкой детализации ASCII и Unicode рисуются заново под размер экрана, без растягивания маленьких растровых букв. При изменении размера окна, масштаба страницы и масштаба превью происходит перерисовка. Для защиты памяти предпросмотр ограничен 4096 пикселями по стороне и примерно 8 мегапикселями. Экспорт PNG/SVG использует ширину от 1600 пикселей при низкой детализации и до 8192 пикселей по стороне с сохранением пропорций. Сетка символов и пропорции при этом сохраняются. Экспорт и копирование используют полную CPU-конвертацию независимо от метаданных GPU-предпросмотра. Время подготовки кадра, включая передачу в основной поток, показано под холстом и зависит от детализации, набора символов и устройства. Нулевая физическая задержка не обещается. Python API конвертации сохранён для отдельных программных запросов и обрабатывает полученные файлы в памяти без записи на диск. Сервер по умолчанию слушает только `127.0.0.1`. Не открывайте его в интернет без отдельной настройки доступа и ограничений запросов. Шрифты загружаются из Google Fonts; без интернета используются системные шрифты.

## Язык, темы и персонализация

Переключатель в шапке меняет язык интерфейса между русским и английским без перезагрузки. Переведены подписи, доступные имена элементов, сообщения об ошибках, подсказки, палитры и встроенные наборы. Имена пользовательских наборов не переводятся. Числа форматируются через Intl.NumberFormat, а атрибут lang и описание страницы обновляются при выборе языка. При первом запуске используется язык браузера, если доступен, затем сохранённый выбор пользователя.

Кнопка «Оформление» открывает персонализацию: двенадцать тем (Бумага, Полночь, Глубокий океан, Сливовый бархат, Графит, Персиковый свет, Чертёж, Кислотный поп, Марсианская пыль, Неоновый город, Неоновый контур и Cyberpunk), акцентный цвет, плотность, масштаб текста 90–120%, ширина панели 280–440 px, скругление 0–18 px и фоновая сетка рабочей области. Темы меняют только интерфейс, не палитру ASCII-изображения. Ширина панели применяется на широких окнах; на узких экранах используются адаптивные ограничения. «Сбросить оформление» не сбрасывает язык, изображение или его коррекции.

Оформление, язык, имя файла и параметры экспорта хранятся в localStorage под ключом AmuzASCII.ui.v1. Это локальные настройки конкретного браузера и адреса.

### Добавление переводов

Русские строки являются исходными ключами. Английский словарь находится в frontend/src/locales/en.json; функции перевода и форматирования — в frontend/src/i18n.js. Для нового языка добавьте JSON-словарь, зарегистрируйте его в messages, разрешите код языка в sanitizePreferences и добавьте вариант в переключатель AppearancePanel.vue. Переменные в сообщениях сохраняйте как {name} и {key}; не вставляйте HTML в переводы. Тесты проверяют покрытие английским всех статических ключей интерфейса и встроенных наборов.

## Выбор формата экспорта

Нажмите «Экспорт» в правом верхнем углу: имя файла, форматы изображения/кадра и видео, качество и сохранение находятся в отдельном диалоговом окне. В правой панели с прокруткой параметров экспорта больше нет. PNG сохраняет изображение без потерь, JPEG и WebP позволяют выбрать качество; SVG содержит векторные символы, TXT — текст, HTML — отдельную страницу с цветным ASCII. Название файла очищается от недопустимых для файловой системы символов; расширение задаётся выбранным форматом. Для JPEG/WebP приложение проверяет фактический MIME-тип созданного файла и не выдаёт PNG под другим расширением.

Для видео доступны серверные форматы MP4 и WebM независимо от MediaRecorder в браузере. Экспорт видео всегда обрабатывает полный исходник с аудио; сохранение произвольного фрагмента и отдельного кадра вместо ролика не предлагается.

## Сохранения и наборы коррекций

Кнопка «Сбросить текущий набор» в разделе «Наборы настроек» возвращает текущие коррекции, цвета, символы и детализацию к начальным значениям, не удаляя сохранённые наборы и медиа. В этом разделе доступны шесть готовых вариантов, включая быстрый режим для видео. Эти же наборы лежат отдельными JSON-файлами в папке `presets/`. Можно сохранить до 100 собственных наборов с именами, выбрать их из списка и удалить ненужные. Набор содержит детализацию, символьную палитру, собственные символы, все коррекции, поворот, отражение, инверсию и параметры цвета.

«Скачать JSON» экспортирует текущие настройки, «Подключить JSON» проверяет, добавляет и сразу применяет набор из файла. Импорт ограничен 1 МБ; неизвестные поля не используются. Последние настройки восстанавливаются при следующем открытии страницы. Сохранения хранятся в localStorage этого браузера и этого адреса сайта; между портами/доменами они автоматически не переносятся. Для переноса используйте JSON. Изображения и видео в набор не включаются — загрузите медиафайл отдельно.

## Серверная обработка видео

Загрузите видео до 250 МБ. Сервер читает файл через PyAV, сохраняет первый кадр и возвращает метаданные. Под холстом доступен ASCII-проигрыватель: воспроизведение и пауза, перемотка, громкость, скорость, частота предпросмотра, повтор и полный экран. Коррекции и палитры применяются к текущему кадру в реальном времени. Неподдерживаемый браузером кодек не блокирует экспорт на сервере.

1. Настройте детализацию, символы, палитру и коррекции в проигрывателе.
2. Откройте «Экспорт» в правом верхнем углу страницы.
3. Выберите MP4 (H.264/AAC) либо WebM (VP9/Opus), задайте имя и запустите обработку.
4. В окне экспорта отображаются количество обработанных кадров и процент обработки. Затем появляется индикатор скачивания с объёмом в МБ и процентом. Готовый файл можно скачать повторно. Окно можно закрыть: текущий этап остаётся виден на кнопке «Экспорт».

Положение ползунка, скорость и FPS проигрывателя влияют только на предпросмотр. Экспорт всегда идёт через бэкенд и включает полный ролик; MediaRecorder не используется. Параметры фиксируются в момент запуска. Все кадры декодируются от начала до EOF, их исходные временные метки сохраняются, включая переменный FPS. Обрабатываются и звуковые дорожки: они перекодируются в AAC или Opus, в стерео. Выходные размеры соответствуют исходнику с учётом поворота; нечётные стороны увеличиваются на один пиксель для кодирования YUV420. Запускается одна задача одновременно, ещё две могут ожидать в очереди.

Результат доступен только после полного завершения и сброса буферов кодировщиков. Ошибка чтения, кодирования, нехватка диска или остановка сервера не приводят к скачиванию обрезанного файла: задача получает статус ошибки, незавершённый файл удаляется. Параметров начала, конца, длительности фрагмента и ограничения размера результата в API обработки нет.

Файлы хранятся временно. Неактивные загрузки и результаты старше часа удаляются при следующем обращении к API; активные задачи не затрагиваются. При штатном завершении сервера его временный каталог очищается. После перезапуска импортируйте видео заново. Размер готового файла может превышать размер исходника — для полного видео нужен свободный диск. Активная задача сохраняется в localStorage этого браузера и адреса. Обновление или закрытие страницы не останавливает серверную обработку; при повторном открытии состояние восстанавливается, пока временные файлы доступны.

PyAV поставляется с библиотеками FFmpeg; отдельный исполняемый `ffmpeg` для работы приложения не требуется. Нужны зависимости из requirements.txt и моноширинный шрифт. Поиск шрифта: `AMUZASCII_FONT`, DejaVu Sans Mono Bold, Consolas Bold, Menlo. Docker устанавливает DejaVu и использует том `/data`, доступный для записи при read-only корневой файловой системе. `TMPDIR=/data` также направляет туда временные multipart-загрузки, чтобы большие файлы не заполняли ограниченный `/tmp`. Для локального каталога временных видео можно задать `AMUZASCII_VIDEO_DIR`.

### API видео

- `POST /api/videos` — multipart `file`; возвращает id, длительность, размеры, FPS, число кадров (если известно), наличие звука и `poster_url`.
- `GET /api/videos/{id}/poster` — первый кадр PNG.
- `GET /api/videos/{id}/source` — исходное видео для восстановления предпросмотра; поддерживает HTTP Range и перемотку.
- `POST /api/videos/{id}/jobs` — JSON: параметры коррекций и цвета, `format`, `fileName`. Возвращает HTTP 202 и id задачи. Поля обрезки не принимаются.
- `GET /api/video-jobs/{id}` — queued / processing / completed / failed, прогресс, число кадров и метаданные результата.
- `GET /api/video-jobs/{id}/download` — только полный завершённый результат. До готовности или при ошибке возвращает HTTP 409.

## Размеры экрана

Редактор адаптируется к размеру окна в CSS-пикселях и плотности пикселей экрана. Физическую диагональ браузер надёжно не определяет. Проверены окна 1366×768, 1536×864, 1920×1080, 2560×1440 и 3840×2160; расчёты также проверены с масштабами плотности 1, 1.25, 1.5 и 2. На широких экранах холст занимает доступное место рядом с настройками; на небольших ноутбуках уменьшаются отступы, а панель настроек прокручивается отдельно. До 650 CSS-пикселей панели располагаются вертикально.

Три дополнительные темы оформляют именно рабочее пространство: «Чертёж» добавляет тонкую координатную сетку и чертёжные разделители; «Кислотный поп» сочетает лаймовую поверхность с фиолетовым акцентом и графичными тенями кнопок; «Марсианская пыль» использует тёплые медные и терракотовые оттенки. Палитра ASCII-изображения остаётся независимой.

Неоновые темы: «Неоновый город» — розово-фиолетовое свечение на тёмном фоне; «Неоновый контур» — бирюзово-мятная схема с координатной сеткой; Cyberpunk — жёлтый акцент, графитовые поверхности и розовые контрастные детали. «Неоновый город» и «Неоновый контур» сочетают по четыре ярких цвета: многоцветные рамки холста, градиентные кнопки, ползунки и полосы прокрутки, цветные фоновые свечения. Свечение статичное, без мерцания; текстовые поверхности сохраняют контраст, а цвета ASCII-арта не меняются. Cyberpunk сохраняет исходное графитовое оформление, жёлтые кнопки с розовой тенью и сдержанные цветные детали.

## API

- `GET /api/health` — состояние сервера.
- `GET /api/demo` — демонстрационное изображение.
- `POST /api/convert` — multipart/form-data: необязательный `file` (без файла используется демо), `columns`, `charset`, `custom`, `brightness`, `contrast`, `saturation`, `gamma`, `rotation`, `mirror`, `invert`.

Ответ: `columns`, `rows`, `lines`, `text`, плоский массив HEX-цветов `colors` и флаг `row_limit_reached`. API независим от live-предпросмотра: Vue не вызывает /api/convert при изменении настроек или загрузке файла. /api/demo запрашивается один раз при старте. Цвета оформления и экспорт выполняются Vue-клиентом.

## Проверки

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest backend -q
cd frontend
npm.cmd run build
npm.cmd test
```

Проверка GPU в браузере: после `npm.cmd run dev` откройте `http://127.0.0.1:5173/tests/preview.html`. Она сравнивает цветовые режимы, прозрачность и коррекции с CPU-конвертером, проверяет точное совпадение контуров шрифта при обычном размере и увеличении в 3 раза и проверяет сохранение сетки в 1000 столбцов. Дополнительная проверка на однотонном поле выявляет горизонтальные полосы при дробном масштабе символов.

Символы используют полужирное начертание; высота строки заполняется по видимым границам выбранного набора шрифта, без стандартного межстрочного поля. Под холстом доступен ползунок «Яркость символов» 0–300% (по умолчанию 120%). Он меняет только цвет букв с ограничением каналов до 255; фон и выбор символов по яркости исходника не меняются. Значение сохраняется в сеансе, наборах и JSON; старые наборы получают прежние 120%. Эти правила применяются к предпросмотру, серверному видео и экспорту изображений/SVG.
Для фото добавлен настоящий SVG-предпросмотр: через 160 мс после последнего изменения параметров worker формирует SVG-маску текстовых строк, если видимая ячейка занимает хотя бы 4 × 6 CSS-пикселей. Для более плотных сеток остаётся фильтрованный LIVE-кадр, чтобы после отпускания ползунка не возникал муар от субпиксельных SVG-штрихов. Выбор режима пересматривается при изменении детализации, масштаба и размера окна. Растровый слой содержит только цвета ячеек, а края символов остаются векторным текстом. После загрузки векторного слоя масштаб и размер окна меняют его размер без растягивания bitmap. Во время воспроизведения worker обновляет ASCII-кадры без очереди устаревших кадров; на паузе возможен SVG-предпросмотр. Полное видео для экспорта обрабатывается на сервере. Если браузер не декодирует SVG, остаётся рабочий Canvas-предпросмотр.
Изображение из буфера обмена вставляется через Ctrl+V (⌘V на macOS), когда фокус находится вне полей ввода и диалогов. Применяются обычные ограничения загрузки изображений; текст и HTML без файла изображения не перехватываются. Во время обработки видео дождитесь её завершения, затем вставьте новое изображение.
В правой панели разделы 01 «Символы» и 02 «Цвет» всегда открыты. Начиная с 03 («Коррекция» и «Наборы настроек») разделы изначально свёрнуты и раскрываются независимо нажатием на заголовок или клавишами Enter/Пробел. Сворачивание не сбрасывает значения.
