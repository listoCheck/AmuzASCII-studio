## Возможности

Загрузите фото или видео, выберите визуальный язык и соберите свой вариант ASCII-арта. Изображения обрабатываются в браузере. Видео загружается на Python-сервер, который конвертирует ролик целиком и отдаёт готовый файл.

| | Что можно настроить |
| :--- | :--- |
| **Символы** | От **40 до 1000 столбцов**, ползунок и ввод с клавиатуры. 14 наборов — от классического ASCII до Брайля — и собственный набор. |
| **Цвет** | 15 палитр, исходные цвета изображения, одноцветный режим, свои цвета букв и фона. |
| **Коррекции** | Яркость, контраст, насыщенность, гамма, инверсия, поворот и отражение. Отдельная **яркость букв 0–300%** под холстом. |
| **Видео** | ASCII-проигрыватель с перемоткой, звуком, скоростью, FPS, повтором и полноэкранным режимом. Экспорт полного видео через сервер с прогрессом обработки и скачивания. |
| **Наборы** | Готовые коррекции, собственные сохранения, импорт и экспорт JSON. Последние настройки восстанавливаются автоматически. |
| **Оформление** | **12 тем**, включая Cyberpunk и две неоновые. Настройка акцента, плотности, текста, панели и скруглений. Интерфейс на **русском и английском**. |

### Экспорт результата

Кнопка **«Экспорт»** в правом верхнем углу открывает отдельное окно сохранения.

| Формат | Для чего |
| :--- | :--- |
| **PNG** | Изображение без потерь. |
| **JPEG / WebP** | Компактный файл с выбором качества. |
| **SVG** | Векторные символы для масштабирования. |
| **TXT** | Чистый ASCII-текст. |
| **HTML** | Отдельная страница с цветным ASCII-артом. |
| **GIF** | Полный анимированный ролик, без звука, с зацикливанием. До 256 цветов на кадр. |
| **WebM / MP4** | Полное ASCII-видео, закодированное на сервере: H.264/AAC или VP9/Opus. |

> Видео обрабатывается **от начала до конца**, с сохранением всех кадров, временных меток и исходного звука. Частичный результат не выдаётся: скачивание доступно только после успешного завершения кодирования.

## Запуск

### Docker Compose

Нужны Docker и Compose v2 с поддержкой Linux-контейнеров. Из корня репозитория:

```bash
docker compose up --build -d
```

Откройте **[http://127.0.0.1:8000](http://127.0.0.1:8000)**. Docker сам соберёт Vue и запустит Python-сервер.

```bash
docker compose logs -f web   # журнал приложения
docker compose down          # остановка
```

Если нужен другой порт, скопируйте `.env.example` в `.env` и задайте, например, `AMUZASCII_PORT=8080`. По умолчанию приложение доступно только на локальном компьютере.

### Локально

**Требования:** Python **3.11+**, Node.js **22.12+**, npm.

После клонирования сначала соберите интерфейс: каталог `frontend/dist` исключён из Git. Затем установите Python-зависимости и запустите сервер.

**Windows / PowerShell** — из корня проекта:

```powershell
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run build

python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run.py
```

<details>
<summary><b>macOS / Linux</b></summary>

npm --prefix frontend run build

python3 -m venv .venv

Откройте **[http://127.0.0.1:8000](http://127.0.0.1:8000)**. Для остановки нажмите `Ctrl+C`.

## Первый ASCII-арт

1. Перетащите изображение или видео на холст, нажмите **«Загрузить фото или видео»** или вставьте скопированное фото через **Ctrl+V / ⌘V**.
2. Выберите детализацию, набор символов и цветовую палитру.
3. Настройте коррекции справа, а яркость букв — ползунком под изображением.
4. Сохраните настройки в набор или скачайте результат через **«Экспорт»**.

Для видео удобно начать с 80–160 столбцов. Для сохранения нажмите **«Экспорт»** в правом верхнем углу, выберите MP4 или WebM и запустите обработку. Полный результат скачивается автоматически; кнопка повторного скачивания остаётся доступной. Высокая детализация увеличивает время обработки, но не обрезает ролик.

## Как это работает

**Vue 3 + Vite** отвечают за интерфейс, **Web Worker** — за обработку вне основного потока. Во время изменения настроек работает быстрый предпросмотр; после короткой паузы изображение с различимыми буквами показывается как настоящий **SVG с текстовыми контурами**. Для плотных сеток с мелкими буквами сохраняется фильтрованный LIVE-кадр: отпускание ползунка не заменяет его на SVG с муаром. Масштабирование SVG не растягивает растровые буквы. Промежуточные кадры предпросмотра используют отрисовку шрифта или **WebGL2**. При недоступности ускоренного пути предусмотрена Canvas-отрисовка.

**FastAPI + Pillow** обслуживают приложение, демонстрационное изображение и API изображений. **PyAV + NumPy + Pillow** конвертируют видео в фоновой задаче, сохраняя исходную временную шкалу и звук. Предпросмотр работает в браузере и не делает запрос к API при каждом изменении ползунка.

Настройки и наборы хранятся в `localStorage`. Медиафайлы в сохранения не входят; для переноса наборов между браузерами используйте JSON.

В хедере при обработке фото и предпросмотре видео отображаются время рендера, доля блокирующих задач основного потока за последние 2 секунды и память JavaScript. Подсказки объясняют измерения; недоступные значения отмечены «—». Это не общая загрузка CPU/GPU: память JS не включает worker, видеопамять и весь процесс браузера.

Серверный рендер использует заранее рассчитанные таблицы смешивания цвета и прозрачности вместо больших временных массивов на каждом кадре. Декодирование использует до четырёх потоков. Это ускоряет обработку без пропуска кадров, изменения детализации или уменьшения разрешения; реальная скорость зависит от устройства и кодека.

### Что учитывать

- Изображения: до **20 МБ** и **25 мегапикселей**. Видео: до **250 МБ**; поддержка кодеков зависит от браузера.
- Детализация — число столбцов; строки вычисляются по пропорциям изображения, максимум **2000**.
- При плотной сетке буква может занимать меньше пикселя экрана: для просмотра её формы нужен больший масштаб.
- Скорость обработки видео зависит от сервера, разрешения и детализации. FPS и временные метки берутся из оригинала; проигрывать ролик на странице не требуется.
- Шрифты интерфейса загружаются из Google Fonts; без сети используются системные замены. Для серверного рендера нужен моноширинный шрифт: в Windows используется Consolas, в Docker установлен DejaVu Sans Mono.

Видео и результаты временно хранятся на сервере. Неактивные записи старше часа очищаются при последующих запросах; после перезапуска сервера прежние временные результаты недоступны. Docker Compose использует отдельный том `/data`, чтобы обработка не упиралась в размер `/tmp`.

## Разработка

Для работы с кодом через AI-агента используйте [AGENTS.md](AGENTS.md): карта файлов, ограничения рендера и команды проверок.

Запустите Python-сервер, а во втором терминале — Vite:

```bash
npm --prefix frontend run dev
```

Интерфейс разработки: **[http://127.0.0.1:5173](http://127.0.0.1:5173)**. Vite перенаправляет `/api` на `127.0.0.1:8000`. На Windows при необходимости используйте `npm.cmd`.

```text
backend/                 FastAPI, Pillow, PyAV и фоновые задачи видео
frontend/src/            Vue, рендерер, темы, переводы и экспорт
frontend/tests/          Проверки рендера в браузере
presets/                 Готовые наборы коррекций в JSON
docs/                    Подробное руководство и скриншоты
Dockerfile               Сборка интерфейса и Python-приложения
compose.yaml             Запуск через Docker Compose
run.py                   Локальный запуск сервера
```

### Проверки

В активированном Python-окружении, из корня репозитория:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest backend -q
npm --prefix frontend test
npm --prefix frontend run build
```

При работающем Vite откройте **[проверки рендера](http://127.0.0.1:5173/tests/preview.html)**: они проверяют коррекции, чёткость букв, яркость, сохранение сетки и горизонтальные полосы.

Подробнее о темах, API, настройках и работе с видео — в **[полном руководстве](docs/guide.md)**.

Во время серверного экспорта метрики в хедере переключаются на CPU и RAM процесса Python и скорость обработки в кадрах/с. В окне экспорта показаны прошедшее время и приблизительный остаток. CPU нормирован на все логические ядра сервера; это не общая нагрузка компьютера. После обработки возвращаются метрики браузера.

Видео обрабатывается конвейером: декодирование, до двух параллельных обработчиков ASCII-кадров и последовательное кодирование в исходном порядке. Очередь ограничена четырьмя видеокадрами и 32 событиями декодирования. При кадрах больше 4 мегапикселей или менее четырёх логических ядер используется один обработчик. Порядок кадров, временные метки, звук и настройки качества кодировщика сохраняются.


### Открытие по ссылке

В правой панели есть поле **«Открыть по ссылке»**: вставьте прямую HTTP/HTTPS-ссылку на фото или видео либо URL одного ролика YouTube и нажмите «Открыть». Показаны прогресс и объём загрузки, доступна отмена. После загрузки доступны те же коррекции, проигрыватель и полный серверный экспорт. Обычные страницы сайтов, каналы, плейлисты и прямые трансляции не импортируются. Лимиты прежние: фото 20 МБ / 25 МП, видео 250 МБ. Файлы сверх лимита отклоняются целиком.

Для YouTube используется `yt-dlp[default]` и Node.js 22+ из PATH; Docker уже содержит Node. Если YouTube изменит защиту или ограничит доступ с IP сервера, обновите пакет: `python -m pip install -U "yt-dlp[default]"`. Закрытые и требующие авторизации видео не загружаются. Источник требований: [документация yt-dlp EJS](https://github.com/yt-dlp/yt-dlp/wiki/EJS).

Локальные фото обрабатываются в браузере; при открытии по URL **ссылка и медиа передаются серверу**. Загрузка допускается только с публичных HTTP/HTTPS-адресов, с проверкой перенаправлений и размеров. При Fake-IP DNS (198.18.0.0/15) реальный публичный адрес уточняется через Cloudflare DNS-over-HTTPS; локальные адреса не разрешаются.

Кнопка полного экрана доступна в подписи холста для фото и видео и в проигрывателе. Повторное нажатие сворачивает просмотр; Esc также работает.

Детализация нового сеанса и сброса настроек по умолчанию — **80 столбцов**; сохранённые пользовательские наборы не изменяются. GIF доступен в «Экспорт → Формат видео». Он сохраняет все кадры, но не звук; палитра ограничена 256 цветами, временные метки округляются до сотых секунды. При исходной частоте выше 100 кадров/с анимация может стать медленнее, чтобы не терять кадры.

При загрузке по ссылке показаны скачанные / общие мегабайты и примерное оставшееся время. Размеры видео и звука YouTube суммируются; предварительный размер помечен ≈ и уточняется по Content-Length. Пока размер или скорость неизвестны, показано «Уточняется»; подготовка после скачивания отображается отдельно. Открытие другого файла освобождает прежнее превью в браузере, но не удаляет серверный исходник, первый кадр и экспорты немедленно. Они очищаются после часа неактивности при следующем обращении к API или при штатной остановке сервера. Скачанные пользователем файлы не удаляются. Отдельные дорожки YouTube удаляются после успешного импорта.
